# YueLink CI queue measurement — 2026-11-13

Sample: latest ten tag push runs and latest ten master runs, ordered by GitHub `created_at`. Master includes push, dispatch and workflow_run events, including skipped results. One master cache warmup was still running; its elapsed window is not a completed duration. The cancelled v1.3.178 run's jobs endpoint was unavailable and remains unknown.

Run admission is `run_started_at - created_at`. Job pending is `started_at - created_at`; job execution is `completed_at - started_at`. Dependencies and runner waiting must not be inferred from run admission alone. Completed run windows also contain dependencies/overlap and are not CPU time. Quantiles use nearest rank for p95. Data comes from GET `/repos/onesyue/yuelink-ci/actions/runs` and `/actions/runs/{id}/jobs`; no runs were dispatched or cancelled.

## Derived effect

The previous Build concurrency key maps every tag and master dispatch to the same `release` suffix. A workflow/ref key removes that collision; its real-world queue reduction cannot be estimated from the zero run-admission samples. GitHub concurrency groups are repository-scoped, so this change does not change yueto-ci capacity or guarantee immediate runner admission.

Coverage join admission is now derived from the coverage producer result. Public attested tag runs skip shards; the join therefore skips before runner allocation instead of checking out source and installing Flutter just to exit. The mandatory preflight still verifies the exact source/builder attestation. Non-tag coverage and failed-shard refusal remain.
